# Research

## Automated Code Generation for Multi-physics Finite Element Solvers with Modern Compiler Infrastructure
Given the popularity and recent advancements in MLIR-based compiler stacks
(commonly used in AI/ML workflows), we propose direct MLIR code generation from
a user-specified specification for solving Partial Differential Equations using
the Finite Element Method. This approach heavily benefits from the existing
optimizations implemented in MLIR compilers (e.g., IREE) while maintaining performance
on different hardware backends (NVIDIA GPU, AMD GPU, x86 CPU, ARM CPU). This
framework is planned to support multivariable, multiphysics scenarios where
the domain experts can quickly and efficiently test new physics models.
<br/>
<small>Ongoing work</small>

## Index Compression for Finite Element SpMV
While all of the literature on optimizing the Sparse Matrix-Vector Multiplication
(SpMV) focus on general matrices, we introduce a provable index compression scheme
for sparse matrices generated by Finite Element Method assembly. We use a domain
decomposition scheme to decompose the SpMV operator into cluster-wise local 
operators which can be compressed using smaller width integers. We prove that
the compression is net positive for the low polynomial order FEM use cases. Optimized SpMV
using this new encoding achieves up to <b>1.7x speedup over SOTA SpMV kernels on NVIDIA
GPUs</b> and up to <b>2x speedup on Intel MKL on x86 CPU</b>.<br/>
<small>Accepted to the Student Research Competition at the 2026 International
Conference for High Performance Computing, Networking, Storage and Analysis (SC '26)<br/>
Full paper pending review.
</small>

## Formal Verification for Finite Element solvers
Collaborative research with <a href="https://tupl.cs.tufts.edu/" 
target="_blank" rel="noopener noreferrer">TuPL</a> for creating a verified code
generation framework for Finite Element solvers. We formalize translating FEM
weak-form into automatically generated backend code to perform quadrature rule
based element-wise integration while ensuring semantic preservation. We use Lean
theorem prover for the implementation. This framework will serve as a 
machine-checkable specification for practical FEM frameworks and provide foundation
for verified PDE solvers.
<br/>
<small>Ongoing work</small>


## AMRaCut: Scalable Partitioning for Adaptive Mesh Refinement
AMRaCut bridges the scalable performance gap between Space Filling Curve based partitioners
and Graph based multi-level partitioners for mesh partitioning in distributed environments.
AMRaCut achieves 5-10x speedup over multi-level partitioners (ParMETIS, PT-Scotch)
on 20,000+ distributed cores while
maintaining maximum partition load within 1.5-2x of optimal, sufficient for
distributed scalability of downstream tasks.
<br/>
<small>
Published in The International Conference for High Performance Computing, Networking, Storage and Analysis (SC '25)
</small>
<br/>
<a href="https://github.com/paralab/AMRaCut" target="_blank" rel="noopener noreferrer"><i class="fa-brands fa-github"></i></a>

## Software Profiling of ALICE O2 at CERN
Profiling the new software suite ALICE O2 developed by CERN for their Run 3. Research involves executing sample workflows, profiling them with memory and CPU profiling tools to identify potential bottlenecks.

## Accelerating k-mer Counting in a Commodity Cluster Environment

Developing an efficient k-mer counting framework specifically tailored for 
commodity clusters (low-end computer networks, university computer labs) which
do not possess high performance networks or file systems. We propose a master-worker
approach where dataset reading is performed in the master node and k-mer counting takes
place in the worker nodes. The complete workflow is pipelined using thread level producer-
consumer approach, accounting for dynamic load balance across worker nodes.
<br/>
Published in Proceedings of the 14th International Conference on Bioinformatics and Biomedical Technology (ICBBT '22)
<br>
<a href="https://github.com/CSE-Optimizers/k-mer_counter" target="_blank" rel="noopener noreferrer"><i class="fa-brands fa-github"></i></a>
